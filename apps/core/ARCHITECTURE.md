# Architecture

```
 Browser — Vite + React SPA (src/)
   src/lib/api.ts          fetch client, credentials:'include', typed ApiError
   src/services/*.ts       thin wrappers — SAME signatures as before; the first
                           `actor` arg is ignored client-side (advisory only)
   src/context/AuthContext /auth/me on mount → { user, permissions, organization }
        │  HTTP /api/*  (session cookie)
        ▼
 Node + Express (server/)
   middleware/auth.ts      attachUser (cookie→req.user) · requireAuth · requirePermission
   app.ts                  one route per operation → calls a domain service with req.user
   services/*.ts           validate (zod-ish) → authorize (RBAC) → assertTenant
                           → repo write → journal → audit → notify
        ▼
   lib/store/Repository.ts   Repository<T> — list/get/query/create/update/remove/count
        ▼
   lib/store/FileRepository   versioned records, 409 on stale expectedVersion
        ▼
   lib/store/FileStore        atomic write (tmp→fsync→rename), per-collection mutex,
                              sha256 checksum, journal, seeding
        ▼
   /data/<collection>.json   + /data/system/journal.log + /data/backups/<id>/
```

Errors → HTTP: `AuthorizationError`/`TenantError` → **403**, `NotFoundError` → 404,
`ConflictError` → **409**, `ValidationError` → 422, `AuthError` → 401/403,
`RateLimitError` → 429, `RecoveryError` → 503. `src/lib/api.ts` rethrows them as
`ApiError` and the existing page error states handle them.

## Folders

| Path | Responsibility |
|---|---|
| `shared/types/index.ts` | every record shape + `CollectionMap` |
| `shared/rbac.ts` | permissions, role bundles, `hasPermission` |
| `shared/config/educationStructures.ts` | configurable levels / grades / study codes |
| `server/lib/store/` | `FileStore`, `FileRepository`, `journal`, `backup`, `recovery`, `checksum`, `mutex` |
| `server/lib/db.ts` | **the swap point** — `new FileRepository(...)` per collection |
| `server/lib/tenant.ts` | `tenantScope`, `scopeRows`, `assertTenant` |
| `server/lib/{password,codes,rate-limit,errors}.ts` | scrypt, id generation, throttling, typed errors |
| `server/services/*.ts` | domain logic (student, teacher, directory, enrollment, transfer, university, report, request, invitation, organization, mentor, message, document, announcement, analytics, settings, user, audit, notification, system, search) |
| `server/middleware/auth.ts` | session + guards |
| `server/app.ts` / `server/index.ts` | routes / bootstrap + recovery + daily backup |
| `server/data/seed/*.json` | initial multi-tenant dump (generated by `server/scripts/generate-seed.ts`) |
| `src/services/*.ts` | client API wrappers (identical exported signatures) |
| `src/pages/**` | portal pages; new: onboarding, admin org/invite/system/backups, school transfers/programs, gov authorize |

## Event chains (spec §43–44)

- `reportService.review(approved)` → update report → notify author → notify
  student (if targeted) → audit `REPORT_APPROVED`.
- `requestService.create` → write request → notify every government user →
  audit; `advance` → update + timeline entry → notify counterparties → audit.
- `invitationService.accept` → create Organization (PENDING) + institution-admin
  User → mark invite ACCEPTED → notify issuer → audit.
- `transferService.advance(accept)` → close old enrolment (TRANSFERRED) → open
  new enrolment at destination → move student + user `organizationId` → notify
  both institutions → audit. **History is never destroyed.**

## Verification

`npm run typecheck && npm run lint && npm test && npm run build` all pass. The
test suite (`server/test/platform.test.ts`, 22 cases) covers tenant isolation,
integrity/recovery, optimistic concurrency, onboarding and backup/restore. A CDP
sweep renders all 74 client routes across the 6 portal contexts with no console
errors.
